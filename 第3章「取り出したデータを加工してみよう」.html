1

集計関数ってなんだろう？

RDBMS には、データベースの中のデータを 集計したり操作したりする ための 関数というしくみが用意されています。関数にデータや条件を渡すと、何らかの処理をして結果を返してくれます。

関数に渡すデータや条件のことを 引数（ひきすう）、関数から返ってくる結果を 戻り値（もどりち）と呼びます。

その中でも、テーブルにあるカラムの 合計値や平均値 など、たくさんの数値から 1つの結果 を返す関数を 集計関数といいます。

▲ 集計関数は、カラムに並んだたくさんの値を「まとめて計算」して、1つの答えを返します。

この章で使う集計関数は5つ。どれもすべての RDBMS で使えます。

▲ カッコ内のよみ方：COUNT（カウント）／SUM（サム）／AVG（エイブイジー）／MIN（ミン）／MAX（マックス）。
関数は RDBMS によって独自のものがあったり、同じ名前でも引数の数がちがったりするよ。でもこの5つは どの RDBMS でも使える から安心してね🍋
2

COUNT でレコード数を数える

集計関数を使う SQL文の基本の形は、関数名のあとに引数を（）で囲むだけ。とてもシンプルです。

書式：関数を使う基本の形
SELECT 関数名(引数) FROM テーブル名;

COUNT関数ですべてのレコード数（＝データの件数）を数えるときは、引数に 「*（アスタリスク）」 を指定します。

SQL文 ── chap3-1.sql
SELECT COUNT(*) FROM sales;

SELECT句で関数を使うと、見出しには 「関数名と引数」 がそのまま表示されます。ASキーワードを使うと、見出しに好きな別名を付けられます。

SQL文 ── chap3-2.sql
SELECT COUNT(*) AS records FROM sales;

💡 コラム：COUNT の引数にカラム名を指定したら？

COUNT関数の引数には、* のかわりに カラム名 を指定することもできます。その場合、値が NULL値 ではないレコードだけが数える対象になります。

NULL値とは、セルにデータが入っていない（空っぽの）ことを表す特別な値のことです。

3

合計・平均・最小・最大を求める

数を数えられたら、次は 合計・平均・最小・最大。使い方は COUNT とまったく同じで、引数に対象のカラム名を入れるだけです。

SUM合計値を求める

SUM関数で、price カラムの値をすべて合計します。

SQL文 ── chap3-3.sql
SELECT SUM(price) FROM sales;
AVG平均値を求める

AVGは Average（＝平均値）の略。1日あたりの平均売上などを調べるのに便利です。

SQL文 ── chap3-4.sql
SELECT AVG(price) FROM sales;
MIN / MAX最小値と最大値を求める

MIN（Minimum＝最小）と MAX（Maximum＝最大）。関数も 「,（カンマ）」で区切れば同時に使えます。

SQL文 ── chap3-5.sql
SELECT MIN(price), MAX(price) FROM sales;

数値だけでなく、文字列で表した日付にも MIN・MAX が使えます。

SQL文 ── chap3-6.sql
SELECT MIN(date), MAX(date) FROM sales;
日付で最小・最大を探すときは、形式がそろっていることが大事。2023-04-10 のように書き方が統一されていないと、正しい結果が得られないから注意してね。
4

GROUP BY でグループにまとめる

ここまでは「テーブル全体」を集計してきました。でも本当に知りたいのは 「お客さんごと」「商品ごと」の集計のはず。そこで登場するのが GROUP BY句（＝グループ分けする）です。

書式：GROUP BY 句の基本
SELECT カラム名, 関数(引数) FROM テーブル名 GROUP BY カラム名;

GROUP BY は集計関数と組み合わせて使います。テーブル名のあとに GROUP BY でまとめたいカラムを指定すると、そのカラムの値ごとにグループを作り、グループごとに集計してくれます。

▲ customer の値ごとにグループを作り、グループごとに COUNT。お客さんごとの来店回数が分かる。
SQL文 ── chap3-7.sql
SELECT customer, COUNT(*) FROM sales GROUP BY customer;
大事なルール：GROUP BY でグループ化するカラムは、SELECT句で指定するカラムと同じにします。

試しにルールを破って、GROUP BY と SELECT で ちがうカラム を指定するとどうなるでしょうか。

SQL文 ── chap3-8.sql（うまくいかない例）
SELECT item_name, COUNT(*) FROM sales GROUP BY customer;

👍 正しい書き方

  • GROUP BY のカラムを SELECT でも指定する
  • SELECT customer …GROUP BY customer

🤔 やりがちな間違い

  • GROUP BY と SELECT でカラムがズレる
  • SELECT item_name …GROUP BY customer
SUM商品ごとに合計する

item_name（商品）でグループを作り、グループごとに price を合計します。

SQL文 ── chap3-9.sql
SELECT item_name, SUM(price) FROM sales GROUP BY item_name;
AVG日付ごとに平均する

date（日付）でグループを作り、1日の平均売上額を求めます。

SQL文 ── chap3-10.sql
SELECT date, AVG(price) FROM sales GROUP BY date;
5

GROUP_CONCAT で値を結合する

GROUP_CONCAT関数には、指定したカラムの値を 結合する働きがあります。結合とは、複数の値をつなげて1つの値にすることです。

使い方は COUNT や SUM と同じで、引数に 結合したいカラム名 を入れます。

SQL文 ── chap3-11.sql
SELECT customer, GROUP_CONCAT(item_name) FROM sales
GROUP BY customer;
GROUP_CONCAT でつなげた値の間には 「,（カンマ）」が入ります。このように値を区切る文字を 区切り文字と呼びます。

同じ商品を何度も買っていると、値が重複して表示されます。DISTINCTキーワードを付けると、重複を取り除いた 結果が得られます。

書式：関数の引数に DISTINCT を付ける
GROUP_CONCAT(DISTINCT カラム名)
SQL文 ── chap3-12.sql
SELECT customer, GROUP_CONCAT(DISTINCT item_name) FROM sales
GROUP BY customer;
6

HAVING でグループに条件をつける

グループ化して集計した結果に対して 条件をつけたい ときは HAVING句を使います。「レコードが2件以上のお客さんだけ」といった絞り込みができます。

書式：HAVING 句の基本
SELECT カラム名, 集計関数 FROM テーブル名
GROUP BY カラム名 HAVING 条件式;

次の SQL文では、customer でグループ化したうえで、レコードが2件以上あるグループだけを取り出しています。

SQL文 ── chap3-13.sql
SELECT customer, COUNT(*) FROM sales
GROUP BY customer HAVING COUNT(*) >= 2;

🔑 WHERE句と HAVING句の違い
どちらもレコードを絞り込む条件ですが、効くタイミングがちがいます。WHERE句は グループ化する前のデータに、HAVING句は グループ化したあとのデータに条件をつけます。

▲ WHERE は「行」を、HAVING は「グループ」を絞り込む。だから WHERE では集計関数は使えません。

句には実行される順番があります。SQL文は書いた順番どおりに実行されるとは限りません。

実行される順番：FROM句 → WHERE句 → GROUP BY句 → HAVING句 → SELECT句
SQL文 ── chap3-14.sql
SELECT customer, COUNT(*) FROM sales
WHERE customer <> 'ウサ田'
GROUP BY customer HAVING COUNT(*) >= 2;
グループ化する前にできるだけ WHERE で絞っておくと、SQL文が読みやすくなるよ。「行の条件は WHERE、グループの条件は HAVING」と覚えよう🍯
7

ORDER BY で並べ替える

ORDER BY句を使うと、取り出したデータを 指定したカラムの値で並べ替えられます。ORDER はここでは「順番」という意味で使われています。

書式：ORDER BY 句の基本
SELECT * FROM テーブル名 ORDER BY 並べ替え基準のカラム名;

次の SQL文は price カラムを基準にしているので、代金が安い順に並んで出力されます。

SQL文 ── chap3-15.sql
SELECT * FROM sales ORDER BY price;

並べ替え基準のカラム名のあとに DESCキーワードを付けると、大きい方から小さい方へ並べ替えられます。

書式：大きい順に並べる
SELECT * FROM テーブル名 ORDER BY カラム名 DESC;
SQL文 ── chap3-16.sql
SELECT * FROM sales ORDER BY price DESC;

⬆️昇順（ASC）

Ascending ／ アセンディング

小さい方から大きい方へ。DESC を書かないと自動的にこちらになります。

⬇️降順（DESC）

Descending ／ ディセンディング

大きい方から小さい方へ。並べ替え基準のカラム名のあとに DESC を書きます。

つまり ORDER BY price; は ORDER BY price ASC; と同じ意味です（ASC は省略されているだけ）。
複数指定並べ替え基準を2つ以上にする

まず item_count だけで並べ替えると、個数が同じ「3」でも price は 360／600 と、きれいには並びません。

SQL文 ── chap3-17.sql
SELECT * FROM sales ORDER BY item_count DESC;

そこで並べ替え基準を 「,（カンマ）」で複数つなげます。1つめが同じ値のときは、2つめの基準でさらに並べ替わります。

書式：並べ替え基準を複数指定
SELECT * FROM テーブル名
ORDER BY カラム名1 DESC, カラム名2 DESC;
SQL文 ── chap3-18.sql
SELECT * FROM sales ORDER BY item_count DESC, price DESC;
8

句を組み合わせる・実行される順番

いよいよ総まとめ。これまでの句を組み合わせて、複雑な SELECT文を作ります。ポイントは 句が実行される順番です。

▲ 書く順番では SELECT が先頭でも、実行は5番目。だから ORDER BY は SELECT のあとに動きます。
組み合わせ①WHERE ＋ ORDER BY

条件で絞り込んだデータを並べ替えます。WHERE の条件式のあとに ORDER BY を書きます。

SQL文 ── chap3-19.sql
SELECT * FROM sales WHERE item_name = 'バナナ' ORDER BY price;
組み合わせ②GROUP BY ＋ ORDER BY

グループ化して集計した数値でも並べ替えられます。ORDER BY に SELECT と同じ集計関数を指定します。

SQL文 ── chap3-20.sql
SELECT item_name, SUM(item_count) FROM sales
GROUP BY item_name
ORDER BY SUM(item_count) DESC;
組み合わせ③ここまでの句を全部使う

WHERE・GROUP BY・HAVING・ORDER BY をすべて組み合わせた、この章の集大成です。

SQL文 ── chap3-21.sql
SELECT item_name, SUM(item_count) FROM sales
WHERE item_name <> 'バナナ'
GROUP BY item_name HAVING SUM(item_count) > 2
ORDER BY SUM(item_count) DESC;
実行される順番（chap3-21）：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。
グループ化したあとの HAVING・SELECT・ORDER BY では 集計関数が使えます。

⚠️ コラム：WHERE句で集計関数を使うとエラー

WHERE句はグループ化する 前 に実行されるため、集計関数（SUM など）は使えません。試すとエラーになります。

SQL文 ── chap3-22.sql（エラーになる例）
SELECT item_name, SUM(item_count) FROM sales
WHERE SUM(item_count) > 2
GROUP BY item_name;

絞り込みたい条件が集計関数なら、WHERE ではなく HAVING を使いましょう。

思ったとおりの結果が出ないときは、句の実行順序と 条件式を見直すのが近道。短い SQL文で順番をしっかり押さえておこう🍓
9

まとめ：この章で覚えた文法

おつかれさまでした🎉 第3章では、取り出したデータを「加工」する方法をたくさん学びました。大事な言葉を並べておきます。

集計関数：たくさんの値から1つの結果を返す関数
COUNT：レコード数（件数）を数える
SUM / AVG：合計値／平均値を求める
MIN / MAX：最小値／最大値を求める
AS：見出しに別名を付ける
GROUP BY：カラムの値でグループにまとめる
GROUP_CONCAT：値をつなげて結合する（DISTINCTで重複除去）
HAVING：グループ化したあとに条件をつける
ORDER BY：並べ替える（DESC＝降順／ASC＝昇順）
実行順：FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY
集計・グループ化・並べ替えができれば、データはぐっと「使える情報」に変わるよ。ここまで来たら、もう立派な SQL の使い手だね！おたのしみに🍓
