SECTION 29

GitHub PagesでWebページを公開してみよう

GitHub Pages（ギットハブ・ページズ）ってなに？

GitHubが提供するWebページ公開サービス。GitHubのアカウントがあれば、無料でWebページを公開できます。

リポジトリに置いたHTMLなどのファイルが、そのままインターネット上のWebページになるイメージです。

GitHub Pagesは、静的なWebページ（HTML・CSS・JavaScript）を公開するサービスです。動的なWebページは公開できません。

OK静的なWebページ

  • HTML・CSS・JavaScriptでできたページ
  • 置いてあるファイルを、そのまま表示する
  • 例：自己紹介ページ、作品紹介、資料ページ

NG動的なWebページ

  • サーバー側でプログラムを動かして、内容を作るページ
  • 見る人や操作によって、表示が変わる
  • 例：ログインが必要な会員サイト、掲示板

⚠ 注意

プライベートリポジトリであっても、GitHub Pagesで公開設定をするとインターネット上で公開されます。見られて困る情報が入っていないか、公開前に必ず確認しましょう。

Webページを更新したいときは

ソースコードを編集後、masterブランチにコミット → プッシュすれば、随時Webページが更新されます。これまで学んだ操作そのままです。

  1. ソースコードを編集する自分のPC
  2. masterブランチにコミットする自分のPC
  3. プッシュする自分のPC → GitHub
  4. Webページが更新される 🎉GitHub Pages

※最近は本流のブランチ名が「main」の場合も多くあります。どのブランチを公開するかはGitHub Pagesの設定で選べます。
※サービスの内容は変更されることがあります。最新の情報はGitHubの公式サイトで確認しましょう。

SECTION 30

Gitを使うとうれしいこと

最後に、Gitを使うとチームにとってどんなうれしいことがあるのかを整理します。大きく2つあります。

1

効率的にコミュニケーションができる

エンジニア・Webデザイナー・ディレクター、全員が同じツールを使うことで、情報の行き違いや伝達漏れが減ります。

職種が違っても、見ている場所はひとつ。
👀状況が見えるチームの誰もが、今のプロダクトの状態・今ディスカッションされていることを確認できる
🙋自分から提案できるプルリクエストを送って自分から提案していくことができる
🤝みんなで決めるそのプルリクエストに対し、いろいろな人の手や意見が入り、チームの合意ができたところでマージされる
意思決定プロセスの民主化

3つ目のような流れのことを、こう呼びます。一部の人だけが決めて上から伝えるのではなく、誰でも提案でき、みんなの意見が入り、チームが合意してから決まる。Gitとプルリクエストが、そんなフラットなチームづくりを支えてくれます。

2

新しく参加した人でもすぐにプロジェクトに入っていける

ソースコードの変更履歴と合わせて、「なぜそうしたのか」という理由がコードレビューやイシューに記録されているので、新しく参加した人でもすぐにプロジェクトに入っていけます。

😣 記録が残っていないと
「このボタン、なんでこの色なんですか？」と毎回だれかに聞くしかない。聞ける人がいなければ、分からないまま。
😊 Gitで記録が残っていると
履歴・レビュー・イシューをたどれば、「いつ・誰が・なぜ」変えたのかを自分で調べられる。
イシュー（issue）ってなに？

GitHub上で、課題・バグ報告・やりたいこと・話し合いを記録しておける掲示板のような機能です。「何が問題で、どう決まったか」が残ります。

CHAPTER1で見た「修正した意図を伝えたい」という悩みが、チーム全体で解決されている状態です。
