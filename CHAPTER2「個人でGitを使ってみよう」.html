SECTION 03

Gitを簡単に使えるツールをインストールしよう

Gitというと、黒い画面（文字だけを打ち込んで操作する画面）で操作するイメージがあるかもしれません。しかし昨今では、グラフィカルなインターフェイスで直感的に操作できる Source Tree（ソースツリー） というツールが登場しました。

同じGitの操作でも、Source Treeならボタンをクリックするだけ。履歴も目で見てわかります。

Source Treeの特徴

🗾日本語対応メニューも日本語で安心
🆓無料お金をかけずに始められる
🔗GitHubなどと連携可能チームでの共有にもそのまま使える
SECTION 04

リポジトリを作ろう

リポジトリってなに？

過去の状態を記録できる貯蔵庫のこと。任意の時点に戻りたいときに、この貯蔵庫からひっぱってくることができます。

イメージは「アルバム付きの倉庫」。ファイルの“その時の姿”を写真のように次々としまっておき、見たい時点の写真を取り出せます。

ソースコード（プログラムの文章）以外にも、いろいろなファイルを管理できます。

  • 📄 ソースコード
  • 🖼️ 画像
  • 📊 Excel・Word
  • 🧊 3Dモデリングデータ

Gitは複数メンバーでの作業に真価を発揮しますが、1人で作るときにも十分活用できます。手元のパソコン内のリポジトリは、ローカルリポジトリと呼ばれています（「ローカル」＝自分の手元、という意味）。

作成したフォルダ内に「.git」という半透明のフォルダが入っていれば、リポジトリに設定されています。
コマンドで操作する場合（黒い画面を使う人向け・読み飛ばしてもOK）
$ mkdir sample ← sampleディレクトリを作成
$ cd sample ← sampleディレクトリに移動
$ git init . ← 今いるディレクトリをGitリポジトリとして設定する

※「ディレクトリ」は「フォルダ」と同じ意味です。

SECTION 05

コミットしてみよう

リポジトリに変更を記録することを コミット といいます。
変更を記録するための基本の流れは、次の3ステップ。記念写真を撮る流れにたとえると分かりやすいです。

✏️1. 作業するファイルを作ったり直したりする
🎭2. ステージする撮影台に載せる
📸3. コミットするスナップショットを撮る
撮影台に載せたものだけが写真に写る ── だから「記録したいもの」だけを選べます。

リポジトリに設定されているフォルダ内に、ファイルが作成されたり変更されたりすると、Source Treeが自動で察知してくれます。

なぜ「ステージ」という一手間があるの？

ステージングエリア（撮影台）に移動させることで、変更したけどまだコミットしたくないファイルがあった場合、別々にコミットすることができます。
たとえば「トップページの修正」と「書きかけのメモ」を、ごちゃまぜにせず別の記録として残せます。

コマンドで操作する場合（読み飛ばしてもOK）
$ git status ← 作業ディレクトリの状態を確認する
$ git add ファイル名 ← 指定したファイルをステージする
$ git commit -m "コミットメッセージをここに書く" ← コミットメッセージを添えてコミットする

※「コミットメッセージ」は、その変更の内容や理由を書くメモ欄です。CHAPTER1で見た「なぜ修正したか」の記録になります。

SECTION 06

チェックアウトでコミットを移動してみよう

チェックアウトをすると、作業ディレクトリ内のファイルを指定した時点と同じ状態にできます。
過去のコミットにも最新のコミットにも進むことができ、やっていることは「今いるコミットを移動するだけ」。記録そのものが消えるわけではありません。

「今ここ」の目印を動かすイメージ。もちろん、また最新のコミットに戻ることもできます。
コマンドで操作する場合（読み飛ばしてもOK）
$ git checkout コミットID ← 指定したコミットに移動する

※「コミットID」は、コミットひとつひとつに自動で付けられる番号（背番号のようなもの）です。

集中型バージョン管理システムと分散型バージョン管理システム

バージョン管理システムには、大きく2つのタイプがあります。Gitは分散型です。

集中型

  • ひとつのリポジトリに接続してみんなで使う
  • 全ての操作はネットワークに接続した状態で行われている
  • コミットは即時、中央リポジトリに反映される
  • CVS・Subversionなど

分散型← Gitはこっち

  • 各自、パソコン上にリポジトリを持ち好きなタイミングで同期する
  • ネットワークに接続しなくても個人のパソコンの中で履歴が見られる
  • コミットを整理して好きなタイミングで同期
  • 個人のパソコンの中で過去に戻せる
  • PC同士やサーバ同士で繋ぐことも可能
  • Git・Mercurialなど

ひとことで言うと

集中型は「みんなで1冊のノートに直接書き込む」。分散型は「各自が自分のノートを持っていて、好きなときに内容を突き合わせる」。
だから分散型のGitは、ネットにつながっていなくても自分のパソコンだけで記録したり過去に戻ったりできるのです。

SUMMARY

まとめ

  • リポジトリとは、過去の状態が記録されている貯蔵庫のこと
  • 「.git」というフォルダが、リポジトリの証
  • 「ファイルに変更を加える → ステージする → コミットする」を繰り返すことで、歴史が記録されていく
  • チェックアウトをすると、指定した時点のデータを、作業ディレクトリにロードできる
