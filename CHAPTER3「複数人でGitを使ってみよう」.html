CHAPTER2では「自分のパソコンの中」だけでGitを使いました。この章では、インターネット上のGitHubを“みんなの集合場所”にして、複数人で作業する方法を見ていきます。

リモートリポジトリってなに？

GitHubなどインターネット上に置かれたリポジトリのこと。自分のパソコンの中にある「ローカルリポジトリ」と対になる言葉です。（リモート＝離れた場所）

SECTION 07

GitHubのアカウントを作ろう

GitHubは、無料で公開リポジトリ・非公開リポジトリを何個でも作ることができます。

無料フリープラン

  • 公開・非公開リポジトリを何個でも作れる
  • ただし、非公開リポジトリ1つあたりの共同作業者は3人までという制限付き

有料有料プラン

  • 何人でも共同作業者を追加できるようになる

※「公開」は誰でも見られるリポジトリ、「非公開」は招待した人だけが見られるリポジトリです。
※料金プランの内容は変更されることがあります。最新の情報はGitHubの公式サイトで確認しましょう。

SECTION 08

SSH接続の設定をしよう

SSH（エスエスエイチ）ってなに？

安全性の高い通信方法のひとつで、すべての通信が暗号化されます。そのため、簡単には解読できず、なりすましも防止できます。

SSHでは、公開鍵と秘密鍵と呼ばれる特殊なファイルを2つ、ペアで使います。
イメージは「GitHubに南京錠（公開鍵）を預けて、その鍵（秘密鍵）は自分だけが持っている」状態。悪意のある第三者は秘密鍵を持っていないので通信できません。

ペアの鍵を持っている者同士だけが通信できる。途中で盗み見ても中身は読めません。

※秘密鍵はその名のとおり、絶対に他人に渡してはいけないファイルです。

SECTION 09

練習用のリポジトリをコピーしてこよう

GitHub上で公開されているリポジトリをコピーする流れは、次の2ステップです。

🍴1. フォークするGitHub上で自分のアカウントにコピー
💻2. クローンする自分のパソコンにダウンロード
フォークはGitHub上でのコピー、クローンはGitHubから自分のパソコンへのダウンロード。

フォークすると、他の人が公開しているリモートリポジトリを、自分のアカウントにコピーできます。

フォークしただけではGitHub上でコピーしただけなので、自分のパソコンにはリポジトリはありません。このリモートリポジトリを、自分のパソコンにダウンロードする操作をクローンと呼びます。

コマンドで操作する場合（読み飛ばしてもOK）
$ git clone 自分のリモートリポジトリのURL ← リモートリポジトリをクローンする
SECTION 10

並行世界を作ろう（ブランチ）

ブランチ（branch＝木の枝）ってなに？

同時並行で作業するときに便利な機能。別のブランチで変更があったとしても、その影響を受けずに開発を続けられます。つまり、並行世界を作れるということです。

本流とは別の「枝」で作業すれば、お互いの変更に影響されずに進められます。

ブランチの移動にはチェックアウト（CHAPTER2で学んだ機能）を使い、今いるブランチから別のブランチへ移動することができます。

※ブランチの正体は「今ココ！」を指す目印（ポインタ）です。枝をまるごと複製しているわけではないので、気軽に作れます。

コマンドで操作する場合（読み飛ばしてもOK）
$ git branch ← 存在するブランチを一覧表示する
$ git branch ブランチ名 ← 現在のブランチを元に新規ブランチを作成する
$ git checkout ブランチ名 ← 指定したブランチに移動する
SECTION 11

ブランチを統合してみよう（マージ）

変更した内容を元のブランチに合流させたいときはマージをします。並行世界を、ひとつの世界に戻すイメージです。

枝分かれして作った変更が、本流に合流します。

実際の開発では、「バグ修正が完了したのでmasterブランチに取り込む」「その間に新機能が完成したため、masterブランチに取り込む」というように役立ちます。

※「master」は本流となるブランチによく付けられる名前です。最近は「main」という名前もよく使われます。

コマンドで操作する場合（読み飛ばしてもOK）
$ git checkout ブランチA ← まずはマージコミットを作りたいブランチAに移動する
$ git merge ブランチB ← マージしたいブランチBを指定してマージする
SECTION 12

プッシュしよう

ローカルリポジトリ（自分のPC）で起きた変更を、リモートリポジトリ（GitHub）に反映させたいときはプッシュをします。アップロードに近いイメージです。

コマンドで操作する場合（読み飛ばしてもOK）
$ git push リモートリポジトリ名 ブランチ名 ← ローカルリポジトリで行った変更を、リモートリポジトリにプッシュする
SECTION 13

プルしよう

リモートリポジトリ（GitHub）で起きた変更を、ローカルリポジトリ（自分のPC）に反映したいときはプルをします。ダウンロードに近いイメージです。

プッシュとプルは、向きが逆なだけ。自分の変更を届けるのがプッシュ、みんなの変更を受け取るのがプル。
コマンドで操作する場合（読み飛ばしてもOK）
$ git pull リモートリポジトリ名 ブランチ名 ← リモートリポジトリ上のコミットを、ローカルリポジトリの現在のブランチに取り込む
SECTION 14

コンフリクトが起きたら？

コンフリクト（conflict＝衝突）は、同じ行に、同時に別々の修正がなされたときに発生します。

😊 違う行を修正した場合
同じファイルでも、行が違えばコンフリクトは起きずにそのままマージされる。
😣 同じ行を修正した場合
Gitは「どちらを採用すればいいの？」と判断できず、コンフリクトになる。

コンフリクトが起きたファイルをエディタで開くと、記号を目印として2つの修正がテキストに入っています。正しいソースコードだけ残して、不要な記号を消すことで、コンフリクトは解決され、マージコミットが作られます。

コンフリクトが起きたファイル
<<<<<<< HEAD
<h1>ようこそ</h1>
=======
<h1>いらっしゃいませ</h1>
>>>>>>> ブランチB
→
正しい方だけ残して、記号を消す
<h1>ようこそ</h1>

※上側（<<<<<<< と ======= の間）が今いるブランチの内容、下側（======= と >>>>>>> の間）がマージしようとしたブランチの内容です。

SECTION 15

プルリクエストからマージまで

プルリクエスト（略して「プルリク」）ってなに？

自分がした変更を取り込んでもらうよう、提案すること。プルリクエストのゴールは、本流のブランチにマージされることです。

😣 コードレビューがない場合
個人が書いたコードが、他のメンバーにチェックされることなく、そのまま本流のブランチに適用されてしまっている状態。この状態だと、バグや目的からずれた実装を生みがち。
😊 プルリクエストを使ったコードレビューがある場合
レビュー担当者が、提案されたコードをチェックし、OKが出たコードだけがマージされる。こうすることで、品質の高いコードを保つことができる。

プルリクエストからマージまでの流れ

  1. フォークするGitHub
  2. クローンするGitHub → 自分のPC
  3. 作業用のブランチを作ってコミットする自分のPC
  4. プッシュする自分のPC → GitHub
  5. GitHub上でプルリクエストを作成するGitHub
  6. コードがレビューされるGitHub

これまでに学んだ操作が、すべてこの流れの中でつながっています。レビューでOKが出れば、本流のブランチにマージされてゴールです 🎉

SECTION 16

バージョン管理しなくてもいいファイルを無視しよう

フォルダの中には、記録しておく必要のないファイルもあります。

バージョン管理が必要ないファイル

  • 🖥️ OSが自動生成するファイル
  • 🗃️ キャッシュ（一時保存データ）
  • 🐘 容量が大きすぎるもの など

除外するファイルの例

ファイル・ディレクトリ名説明
.DS_StoremacOSが自動で生成
Thumbs.dbWindows OSが自動で生成
.sass-cache/Sassのキャッシュ。管理が必要ないため、除外する
*.css.mapSassのソースマップ。Sassの適用箇所をたどるために出力するもの。管理が必要ないため、除外する

このような場合、「.gitignore」（ギット・イグノア：ignore＝無視する）というテキストファイルを使うと、Gitで管理しないファイルを指定することができます。

「.gitignore」の書き方

特定のファイルを無視したい

# 自分用のメモファイルを無視する
memo.txt

特定の拡張子を無視したい

# .rbcという拡張子がついているファイルが無視される
*.rbc

特定のファイルを無視しない（例外設定）

# 例外として、test.rbcは無視されない
!test.rbc

特定のディレクトリ以下を無視したい

# templates_cというディレクトリ以下が無視される
templates_c/

ルートディレクトリ直下にあるものを指定したい

# ルートディレクトリにあるlogというディレクトリ以下が無視される
/log/

コメント

# 行頭に#を入力するとコメントが書ける

※「*」は「なんでもOK」という意味の記号です。「ルートディレクトリ」はリポジトリのいちばん上のフォルダのことです。

すでにコミットしてしまったファイルを無視する方法

  1. 追跡をやめる
  2. 「.gitignore」に追加する

※一度記録したファイルは、.gitignoreに書くだけでは無視されません。先にGitの「追跡」から外す必要があります（コマンドでは git rm --cached ファイル名）。

SUMMARY

まとめ

コピーとブランチ

  • フォークとは、他人が公開しているリモートリポジトリを、自分のアカウントに、クラウド上でコピーする機能
  • クローンとは、クラウド上のリモートリポジトリを自分のパソコンの中にダウンロードする機能
  • ブランチとは、ポインタである
  • ポインタとは、簡単に言うと「今ココ！」である
  • ブランチを移動するときは、チェックアウトを使う

統合とやり取り

  • マージは、ブランチを統合することができる
  • アップロードしたいとき → プッシュ
  • ダウンロードしてローカルリポジトリに反映したいとき → プル
  • コンフリクトした箇所を、Gitが印をつけて教えてくれる
  • エディタで修正してコミットし直す
