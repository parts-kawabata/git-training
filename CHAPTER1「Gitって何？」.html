はじめに

こんな経験、ありませんか？

資料を何度も修正しているうちに、フォルダの中がこうなってしまった……。

企画書.docx
企画書_修正.docx
企画書_最新.docx
企画書_最新_田中さん修正.docx
企画書_本当に最終.docx
企画書_最終_これで確定(2).docx

「で、結局どれが最新なんだっけ？」「3日前の版に戻したいけど、どれ？」

こうした「ファイルの変更をどう管理するか」という悩みを解決してくれる道具が、これから学ぶ Git（ギット） です。

SECTION 01

Gitで解決できること

Gitは バージョン管理システム です。Gitを使うことで、より効率的に開発をすることができます。

バージョン管理システムってなに？

「いつ・誰が・どこを・なぜ変えたか」を記録しておき、あとから見返したり、昔の状態に戻したりできる仕組みのこと。

イメージはゲームのセーブポイント。こまめにセーブしておけば、失敗してもセーブした地点からやり直せますよね。Gitはファイルに対してそれをやってくれます。

では、Gitがあると具体的に何がうれしいのか。よくある3つの悩みで比べてみましょう。

1

過去の状態に戻したい

😣 Gitがないと
バックアップを手動で作成。戻りたい時点のデータがなくて、戻せないことも。
😊 Gitがあると
作業用のフォルダひとつでOK。いつでも、好きな時点に、ファイルの状態を戻せる。
変更のたびに「セーブポイント」を記録。ファイルは1つのまま、好きな時点へ戻れます。
2

同じファイルに対して、複数人で同時に修正を行いたい

😣 Gitがないと
一人一人に修正箇所を聞いて回り、手動でまとめるハメに。
😊 Gitがあると
複数人による修正をまとめることができる。
同時に別々の場所を直しても、Gitが自動でひとつにまとめてくれます。
3

修正した意図を伝えたい

😣 Gitがないと
コードやデザインの意図を知りたいとき、さかのぼって調べることができない。特に前任者がいないときは大変。
😊 Gitがあると
変更内容を細かい単位で記録できるため、誰が何のために修正したのか、Gitの履歴を見れば一目瞭然。
  • 橋本：ボタンの色を青→緑に変更（押せることを分かりやすくするため）
    9月8日 15:20
  • 鈴木：料金表に「税込」表記を追加（お客様からの問い合わせ対応）
    9月5日 11:02
  • 田中：トップページの見出しを短く修正（スマホで2行になっていたため）
    9月3日 17:45
履歴には「誰が・いつ・何を・なぜ」が残ります。前任者がいなくても、変更の理由がわかります。
SECTION 02

コミュニケーションの場としてのGitHub

名前が似ているので混同しやすいのが Git と GitHub（ギットハブ）。まずはこの2つの違いを押さえましょう。

道具Git

  • 自分のパソコンで使う道具
  • ファイルの変更を記録・管理する
  • たとえるなら「セーブ機能」

場所GitHub

  • インターネット上のサービス（場所）
  • Gitで管理しているファイルを置いて、みんなで共有する
  • たとえるなら「チームの共有ノート＋会議室」
各自のパソコンではGitで記録し、GitHubに集まって共有・相談する。

GitHubとは、ファイルを編集しながら、複数人でやり取りし、コミュニケーションする場所です。単なるファイル置き場ではなく、次のようにチームでフラットに意見交換できる場として使えます。

🔍レビューお互いのコードをレビューする
💬話し合い仕様や、機能の実装について話し合う
🎨デザイン共有デザインのビフォーアフターを共有し、意見を出し合う

🌏 世界中とつながれる

GitHubでは、世界中のエンジニア・デザイナーが書いたコードを見ることができます。

さらに、自分が書いたコードを提案し、取り込んでもらうこともできます。見知らぬ誰かの作ったソフトに「ここ、こう直すともっと良くなりますよ」と提案できる ── それがGitHubです。

SUMMARY

まとめ

道具Gitとは

  • バージョン管理システムである
  • 簡単な操作で、変更ごとのバックアップをとることができる
  • いつでも好きな時点に戻せる
  • 各メンバーの修正を合体できる

場所GitHubは

  • Gitで管理しているファイルのバックアップ先として使える場所
  • 単なるファイル置き場ではなく、コミュニケーションの場
